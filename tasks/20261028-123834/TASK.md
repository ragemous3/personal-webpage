### Agreed architecture and read path

Composition supplies the browser storage and storage-event dependencies to a data-layer configuration repository, then injects that repository through a shared contract into a configuration service. Use backend-independent names; do not name the service after localStorage.

The repository owns persistence keys, the serialized record format, schema version, JSON handling, and storage-event filtering. The configuration service calls typed repository methods such as load, save, and observe. It never passes raw storage keys or calls browser storage APIs. The component never accesses storage, workers, or model pipelines.

The configuration service combines validated saved preferences with site/model defaults and exposes a read-only stateful subscription. The component receives the current state on subscription and subsequent updates. Resolve saved preferences before starting model initialization. Inject runtime reconfiguration through a contract; composition wires concrete implementations, and the service coordinates the use case.

## Acceptance criteria

- [x] Only one live model/retrieval runtime is hosted across tabs. Opening another tab must not load another model. RuntimeCoordinator routes requests to the shared generation and retrieval workers and routes streamed/final/error responses back to the requesting tab. Shared model settings apply across tabs; no tab owns the runtime. Conversations and cancellation remain isolated by client and request identity. Do not bypass the shared-worker architecture with independent per-tab models.
- [x] An unstyled configuration web component uses a configuration service through a shared contract and context/composition injection. Mode and Model are separate controls. Model initially has only the existing Qwen choice. Basic and Advanced controls follow the agreed defaults and validate supported values before updating settings.
- [x] The service depends on a typed, injected configuration repository. Persistence keys, JSON, schema version, browser storage access, and storage-event handling stay in the data layer. Composition supplies localStorage and browser event dependencies. Views and services contain no direct localStorage calls or raw persistence keys.
- [x] On startup, the service validates saved preferences, combines them with defaults, and publishes selected settings, active settings, pending/loading state, availability, and errors through a read-only stateful subscription. Subscribers receive the current state immediately. No model starts with defaults before saved preferences have been resolved.
- [x] Local execution passes `auto` unchanged to both the generation and retrieval pipelines. CPU maps to `wasm`, and WebGPU maps to `webgpu`. Remove retrieval's hardcoded WebGPU requirement for this path. Preserve the retrieval model, embedding dimensions, normalization, matching index, and its compatible precision. Use the pipeline/runtime's internal Auto selection; do not add a competing application-level hardware selection or fallback algorithm.
- [x] Valid edits update service state and persisted preferences without an Apply button. Invalid or incomplete input shows field feedback and does not replace the last valid settings. Persist requested Auto values, not a guessed or previously selected physical backend. Do not claim to know the actual provider unless the runtime exposes it reliably.
- [x] An active retrieval/generation response finishes using its starting configuration. Configuration controls stay usable. Multiple edits coalesce into the latest complete valid combination. Apply that combination after the request reaches completion, failure, or explicit cancellation; settings edits themselves never cancel it. If idle, apply changes without waiting for another response. Edits during initialization also coalesce without overlapping uncontrolled model loads or allowing stale initialization to install an older selection.
- [x] During a required runtime replacement, Send stays disabled until the selected configuration is ready. No new question slips through on the old configuration while a pending change is being adopted. Generation-only changes take effect for the next question without reloading model weights. Model/backend/precision changes replace or reuse runtime resources coherently, without orphan workers, duplicate listeners, or termination of resources still owned by another client.
- [x] Changing any setting or mode preserves the current tab's conversation. Only the explicit conversation Reset action clears it. A replacement model receives appropriate retained history. Restore defaults and switching back are configuration operations, not conversation resets.
- [x] Online is selectable and persisted, but displays “Online mode is not available yet” and disables Send. It makes no online inference requests, collects no credentials, and starts no unnecessary local model downloads. If selected during a response, that response finishes before the mode change takes effect. Returning to Local uses the retained local preferences and conversation. Do not pretend the local Qwen model is an online model.
- [x] A failed configuration shows the requested setting/value or combination that failed, the available diagnostic, and a clear prompt to switch back. Do not guess a single culprit when the runtime only identifies a failing combination. Keep the conversation and selected settings visible; Send stays disabled until a configuration loads. Offer an explicit switch-back action to this client's last working configuration and Retry for the failed selection. If no previous working configuration exists, offer Restore defaults without claiming it is guaranteed to solve the failure. Do not silently roll back or answer with a different configuration.
- [x] Saved changes propagate across tabs through the injected repository's observation interface. The shared runtime finishes all accepted responses using their starting configuration before adopting the latest preferences once for all tabs. Each tab keeps its own conversation and can keep editing settings. Ignore unrelated keys and stale callbacks, do not echo received changes into write loops, and ensure an older initialization result cannot overwrite newer preferences. Conversation history is not persisted by this feature.
- [x] Missing saved data uses defaults. Malformed, unsupported-version, or invalid saved preferences cannot crash startup or bypass validation; recover to valid defaults with a visible notice. If storage access or writes fail, allow session-only operation and show that settings will not be remembered. Never clear unrelated browser storage.
- [x] Public-interface tests cover loading/defaults, validation, requested-versus-active state, latest-change coalescing, response completion boundaries, configuration failures and switching back, shared resource ownership, stale initialization, and cross-tab updates. Browser component tests cover the actual controls, automatic updates without Apply, pending/error messages, preserved history, and the unavailable Online mode.
