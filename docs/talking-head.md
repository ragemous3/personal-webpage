# Talking head prototype

The assistant shows a centered MPFB avatar in a 320-by-320 mount. Enable speech selects browser speech in Local mode and loads the English Kokoro voice in Online mode after a user action. Stop speech stops the current utterance; a new answer can speak while speech remains enabled. Reset, a replacement question, failures and mode disposal invalidate pending speech. Reload and mode changes require enabling speech again.

Composition supplies the same Local `Chat` or `OnlineChatClient` instance to RagService and TalkingHeadService. RagService alone starts generation. The head observes request-scoped generation events through `ChatGenerationContract`; speech starts from completed answers independently of history saving. `ChatbotServiceContract.lifecycleSubscription` carries invalidation that can happen before generation or after it finishes. Restored history is never the speech source.

TalkingHeadService uses the same synthesis and presentation contracts in both modes. Composition supplies BrowserSpeechAdapter for Local and HeadTTSAdapter for Online. Local passes answer text to the browser's speechSynthesis API through TalkingHeadAdapter. The browser chooses an English voice; available voices and offline support depend on the browser and operating system. Local downloads no Kokoro model and starts no speech Worker. BrowserSpeechLipSync reuses TalkingHead's rule-based LipsyncEn converter to derive mouth shapes from text. Animation starts on the native speech start event. It estimates word durations and adjusts its position on word-boundary events when the browser supplies them. This is approximate synchronization; native speech does not expose phoneme timestamps or a captured audio stream. Stop, completion and errors cancel the frame loop and close the mouth. No additional model or speech Worker is needed. Missing speech support or native voice errors show a plain error while text chat remains usable.

Online uses HeadTTS 1.3.0 and WASM Kokoro inference in one dedicated Worker per enabled tab, separate from the application's three SharedWorkers. TalkingHeadAdapter uses TalkingHead 1.8.2 and Three.js for rendering, audio and Oculus visemes. Stop, Reset, new questions and disposal cancel active playback. Configuration unavailability releases the Online voice worker. Rendering pauses while the head is silent; Online audio playback resumes it. Mode disposal also closes audio contexts and releases the renderer.

The specific avatar is CC0; [its provenance](../static/avatars/README.md) records the source revision and hash. [Third-party notices](../static/speech/third-party-notices.txt) cover the SDKs and runtime. Model weights download at runtime. English is the supported prototype language. Microphone input, additional voice choices and streamed sentence delivery are outside this prototype.

Transformers.js owns model/tokenizer/WASM caching. The worker's fetch wrapper caches voices and dictionaries separately, tolerates unavailable storage, and leaves partial model responses to the model framework. A model cache does not establish that the whole site works offline or that the browser will retain data indefinitely.

## Verification

Run `npm run verify:browser -- --mode speech` with the repository's Hugo and Chromium prerequisites. This uses real MPFB rendering, Online Kokoro speech and Local browser speech, with controlled résumé retrieval and Local/Online generation. It exercises a question through the production UI, Stop/Reset, a browser restart with external DNS blocked, and a Local mode switch. Online audio-buffer observations, Local native utterance events, a screenshot, video, timing measurements and cache URLs remain in the ignored evidence directory after cleanup.

Set `RUNTIME_MODEL_DIR` to the model mirror described in [runtime-coordinator.md](runtime-coordinator.md) to also use real Local generation/retrieval. Online generation still uses the controlled OpenAI HTTP endpoint. No paid TTS credentials are required. Live OpenAI and hardware WebGPU inference are separate claims.

With idle rendering paused, the software-rendered CPU run measured about 28 seconds for cold voice initialization, 6.5 seconds from an Online question to first audio, and 10–11 seconds for the earlier controlled Kokoro cache test. These historical values do not measure Local browser speech. These include the prototype's model/resource policy and are not hardware-wide guarantees.

Before the Local change, a fresh real Qwen/Kokoro session passed, but switching from Online to Local caused an out-of-memory kill while loading speech after generation in this 8 GiB environment. Local now uses browser speech to avoid that voice-model overlap. The verification runner reports BLOCKED if the operating system exposes no usable browser voice; it does not replace native speech with simulated audio or claim audible output from API availability alone.
