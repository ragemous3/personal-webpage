# Talking head prototype

The assistant shows a centered MPFB avatar in a 320-by-320 mount. Both Local and Online use the browser's native speechSynthesis API after Enable speech. Stop speech ends the current utterance; later answers can speak while enabled. Reset, replacement questions, failures and mode disposal invalidate pending work. Reload and mode changes require enabling speech again.

Composition supplies the same Local Chat or OnlineChatClient instance to RagService and TalkingHeadService. RagService alone starts generation. The head observes request-scoped completed answers through ChatGenerationContract; speech is independent of history saving. ChatbotServiceContract.lifecycleSubscription invalidates work before generation or after it finishes. Restored history is never the speech source.

Both mode compositions supply BrowserSpeechAdapter through SpeechSynthesisContract. SpeechOutput carries text. TalkingHeadAdapter owns native speech events and the TalkingHead/Three.js renderer. BrowserSpeechLipSync reuses TalkingHead's statically bundled LipsyncEn rules to derive mouth shapes from text, estimates word durations from text/rate and aligns to native word-boundary events where available. It starts on speech start and closes the mouth on completion, cancellation or error. This is approximate timing, not phoneme timestamps derived from the browser audio.

No neural TTS model, voice download, speech Worker or speech-specific model cache is used. The three application SharedWorkers still own coordination, generation and retrieval. Browser voices depend on the operating system/browser; an available API does not guarantee a usable voice or offline synthesis. Voice failures show a plain status and leave text/history usable. Rendering pauses when idle; disposal closes audio contexts and releases the avatar. See [avatar provenance](../static/avatars/README.md) and [renderer notices](../static/avatars/third-party-notices.txt).

## Verification

Run `npm run verify:browser -- --mode speech` with Hugo and Chromium. This uses real avatar rendering and native speech events in both modes; generation/retrieval and the Online HTTP provider are controlled by default. Set RUNTIME_MODEL_DIR to the mirror described in [runtime-coordinator.md](runtime-coordinator.md) for real Local generation/retrieval. Live OpenAI requires separate verification.

The journey checks Online and Local questions, text-to-utterance correspondence, Stop/Reset, zero speech Workers and returning-browser behavior. It keeps going through text/error paths when zero voices cause synthesis failure, and reports BLOCKED for audible speech. It retains a screenshot, video and observations outside disposable profiles. Browser speech is not captured as Web Audio PCM; no WAV or neural voice cache proof is claimed. A DNS-blocked returning journey tests the application/model path, not universal offline availability of system voices.

The environment currently exposes no system voices, so native audio/alignment needs a voice-enabled browser. Controlled native events and a real SDK/avatar demonstrated mouth opening and closure, with focused timing tests. Those observations do not establish audible synchronization. The earlier neural voice memory experiments remain historical evidence in the prototype ticket; they are not part of the current speech path. [Server audio streaming](../tasks/20261109-114334/TASK.md) is separate planned work.
